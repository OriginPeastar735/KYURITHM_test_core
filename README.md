# KYURITHM（開発中）

だれでも楽しめることをコンセプトにした、専用タッチセンサーコントローラーで遊ぶ音楽ゲーム。

画面の下に左斜面・底面・右斜面の3面からなるタッチセンサーを置き、32本のレーンに流れてくるノーツに触れて遊ぶ。

```
左斜面 8レーン ＼＿＿＿ 底面 16レーン ＿＿＿／ 右斜面 8レーン
   lane 0〜7          lane 8〜23          lane 24〜31
```

## 使用技術

- Unity 6000.6.5f1（URP）
- C#
- Newtonsoft.Json（譜面の読み込み）
- Arduino（専用コントローラー、シリアル通信）

## 画面の流れ

| シーン | 内容 |
|---|---|
| Opening | タイトル |
| MusicSelect | 選曲 → 楽曲確定（難易度・設定） → 楽曲紹介。紹介画面の裏でプレイ画面を読み込む |
| Play | プレイ。全ノーツの判定が終わると同じシーン内にリザルトを表示する |

## ゲームの仕様

### ノーツ

| 種類 | 内容 |
|---|---|
| TAP | 触れた瞬間を判定する |
| HOLD | 判定ライン通過時に触れていれば判定する（長さは持たない）。通過する直前（0.08秒以内）に触れて離していても取れる |
| SLIDE | 区間ごとに直線・内曲がり・外曲がりで動く。始点はTAPと同じく触れた瞬間を判定し、中間・終点と一定間隔の判定点では触れているかを判定する。間隔はその位置のBPMで決まり、BPM120未満は16分、240未満は8分、それ以上は4分。中間ノーツから分岐でき、分岐の接続点は親の中間ノーツとして1回だけ判定する |
| BPM変更線 | ノーツが来るタイミング（秒）だけが変わる。ノーツの流れる速さは常に一定（ソフランにはならない） |

総ノーツ数の数え方は譜面エディタ（`SPEC` コマンド）と同じ。譜面の `meta.totalNotes` と一致しない場合は、読み込み時に警告を出す。

### 判定とスコア

スコアは 1ノーツあたり `1,000,000 ÷ 総ノーツ数` を基準に、判定ごとの割合で加算する。全PRECISEで100万点（ALL PRECISE）、全PRECISE+で101万点（理論値）。

| 判定 | 判定幅 | 加算 |
|---|---|---|
| PRECISE+ | ±40ms | 101% |
| PRECISE | ±70ms | 100% |
| APPROX | ±110ms | 50% |
| MISS | ±130ms以内の早押し・遅押し、または見逃し | 0% |

縦に重なるノーツ（レーンが少しでも重なる位置に続けて来る TAP・SLIDE 始点）は、後ろのノーツを「前のノーツとの中間の時刻」より前に押しても判定しない。前のノーツを叩いた手が後ろのノーツを早押しで巻き込まないようにするためで、間隔が狭いほど悪い判定が出にくくなる（間隔 140ms 以下なら APPROX 以下は出ず、80ms 以下なら PRECISE+ だけになる）。

ハイスコアは筐体の記録としてファイルに保存され、ゲームを終了しても残る（`Application.persistentDataPath` の `highscores.json`。消すとリセットされる）。

### 難易度

PARALLEL / INTERPLAY / ELUSIVE の3種類。ELUSIVEは一部の楽曲のみ。

## 操作

### 専用コントローラー

| 場所 | 選曲画面での役割 |
|---|---|
| 左斜面（上4・下4レーン） | ソート切り替え ← / →（楽曲確定・設定では戻る） |
| 底面（左5・中央6・右5レーン） | 左 / 決定 / 右 |
| 右斜面（下4・上4レーン） | 難易度 − / +（設定では値の変更） |

通信はシリアル（115200bps）。ポートは自動で探す（パケットが届くポートを選ぶ）ので、ポート名を合わせる必要はない。つながったとき・切れたときは画面の上に知らせが出て、切れた場合は自動でつなぎ直す。パケットはヘッダー `0xAA` ＋ 4バイト（lane 0〜7, 8〜15, 16〜23, 24〜31。各バイトのbit0が一番小さいレーン）。

#### コントローラーのつくり

| 項目 | 内容 |
|---|---|
| マイコン | Raspberry Pi Pico ＋ タッチセンサーIC MPR121 ×4（1枚で8レーン：左斜面／底面左／底面右／右斜面） |
| 斜面の角度 | 45度 |
| 電極 | 銅テープ（幅1cmを2本並べて幅2cm）をアクリル板に貼る。上にクリアファイルを貼り、指は電極に直接触れない |
| 大きさ | 押せる範囲は縦10cm。電極どうしのすき間は5mm（2.5cmおきに並ぶ） |
| 配線 | 電極にリード線をはんだ付けしてICへ。長さは5〜10cm（なるべく短く） |

将来は電極をプリント基板に置き換える予定。スケッチは `Arduino/slider32/slider32.ino`（arduino-pico v6.3.0 / Adafruit_MPR121 v1.1.3）。

#### コントローラーへの書き込み・動作確認（VS Code）

Arduino IDE（ボード「Raspberry Pi Pico」とライブラリ入り）がインストールしてあれば、VS Code からも書き込める。書き込み・モニタの前に Unity の再生と Arduino IDE は閉じる（Pico は1つのソフトからしか開けない）。

- 書き込み：`Ctrl+Shift+B`（タスク「Arduino: コンパイルして書き込み」。つないである Pico を自動で探す）
- シリアルモニタ：拡張機能「Serial Monitor」の SERIAL MONITOR タブで、ポートを選び 115200bps で開く。下の欄から1文字のコマンドを送れる

| コマンド | 動き |
|---|---|
| `d` | 診断モード（各キーの変化量を文字で表示。押されているキーに `*`） |
| `b` | Unity 用のモードに戻す（**診断のあとは必ず送る**。忘れたら USB を挿し直す） |
| `s` | 接続状態を表示 |
| `r` | 全センサーを再初期化 |
| `0`〜`3` | そのユニットだけ再初期化（F5 と同じ） |

### キーボード（コントローラー無しでのテスト用）

| キー | プレイ画面 | 選曲画面 |
|---|---|---|
| A / S | lane 0〜3 / 4〜7 | ソート ← / → |
| D / F | lane 8〜11 / 12〜15 | 左 / 決定 |
| J / K | lane 16〜19 / 20〜23 | 決定 / 右 |
| L / ; | lane 24〜27 / 28〜31 | 難易度 − / + |
| F1 | 入力元の切り替え（キーボード / コントローラー / 両方） | − |

選曲画面では ← → Enter Space も使える。

### 運営用キー

| キー | 動き |
|---|---|
| F1 | 入力元の切り替え（キーボード / コントローラー / 両方） |
| F5 | センサーリセット（押しっぱなしになったレーンを直す） |
| F9 | オープニングで画面合わせ・タイミング合わせをやり直す |
| F12 | 全スキップ。どの画面からでも今のプレイを打ち切ってタイトルへ戻る |

### 画面の大きさ合わせ

Windows用ビルドの初回起動時に、ゲームのウィンドウの大きさと位置を筐体のセンサーに合わせる設定画面が出る。操作は [docs/画面の大きさ合わせ.md](docs/画面の大きさ合わせ.md) を参照。

## 譜面

外部のWeb譜面エディタで作成したJSONを使う。

- `meta`：楽曲名・作曲者・難易度・レベル・譜面制作者・音源ファイル名・BPM・オフセットなど
- `notes`：ノーツの配列。位置は `lane`（0〜31）と `width`（レーン数）、時間は `tick`（1小節 = 1920tick、1拍 = 480tick）

## 曲データの置き方

曲データ（譜面・音源・ジャケット）はGoogle Driveで管理していて、**gitには入れない**。Driveから1曲ずつフォルダごと次の場所にコピーする。

```
Assets/StreamingAssets/Songs/<曲フォルダ>/
    譜面JSON（譜面エディタの出力そのまま。難易度ごとに1つ。ファイル名は自由）
    音源ファイル（譜面の meta.audioFileName と同じ名前）
    jacket.png（jacket.jpg でもよい。無ければフォルダ内の最初の画像を使う）
```

- 曲名・作曲者・難易度・レベル・譜面制作者は譜面の `meta` から読むので、曲の情報を書いたファイルは別に作らない
- 難易度は PARALLEL → INTERPLAY → ELUSIVE の順に、低い方から欠けずにそろっている必要がある
- `Songs` に曲が1つも無いときは、選曲画面に仮の曲が表示される（譜面は確認用の `Resources/test_long.json`）
- 読み込めない譜面や足りないファイルがあると、Consoleに警告が出る

## フォルダ構成

```
Assets/
  Scenes/            Opening, MusicSelect, Play, Result, Ending
  Scripts/
    Core/            シーン切り替え(SceneLoader)、シーン間のデータ受け渡し(PlaySession)、曲の読み込み(SongLibrary)、入力(InputManager)、画面合わせ・タイミング合わせ
    GamePlay/        ノーツ・判定・レーン・1曲ごとのリザルト・チュートリアル
    MusicSelect/     選曲画面（UIはMusicSelectViewがコードで生成）、楽曲紹介画面
    Opening/         タイトル画面
    Result/          3曲分をまとめた最終リザルト、コンティニューの質問
    Ending/          エンディング画面
  StreamingAssets/
    Songs/           曲データ（gitには入れない）
  Resources/         テスト用の譜面JSON
  Prefab/            ノーツ・レーンのプレハブ
Arduino/
  slider32/          専用コントローラーのスケッチ（Raspberry Pi Pico）
```

## 共同開発での注意

- Unityのバージョンを 6000.6.5f1 にそろえる（違うバージョンで開くと大量の差分が出る）
- アセットの移動・名前変更はUnity上で行い、`.meta` ファイルも一緒にコミットする
- シーン（特に Play.unity）は同時に編集しない。作業前に `git pull` する
- コントローラーのポート名など、自分の環境に合わせた値をシーンごとコミットしない
