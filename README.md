# KYURITHM（開発中）

だれでも楽しめることをコンセプトにした、専用タッチセンサーコントローラーで遊ぶ音楽ゲーム。

画面の下に左斜面・底面・右斜面の3面からなるタッチセンサーを置き、32本のレーンに流れてくるノーツに触れて遊ぶ。

```
左斜面 8レーン ＼＿＿＿ 底面 16レーン ＿＿＿／ 右斜面 8レーン
   lane 0〜7          lane 8〜23          lane 24〜31
```

## 使用技術

- Unity 6000.6.5f1（URP）
- C#
- Newtonsoft.Json（譜面の読み込み）
- Arduino（専用コントローラー、シリアル通信）

## 画面の流れ

| シーン | 内容 |
|---|---|
| Opening | タイトル |
| MusicSelect | 選曲 → 楽曲確定（難易度・設定） → 楽曲紹介。紹介画面の裏でプレイ画面を読み込む |
| Play | プレイ。全ノーツの判定が終わると同じシーン内にリザルトを表示する |

## ゲームの仕様

### ノーツ

| 種類 | 内容 |
|---|---|
| TAP | 触れた瞬間を判定する |
| HOLD | 判定ライン通過時に触れていれば判定する（長さは持たない） |
| SLIDE | 区間ごとに直線・内曲がり・外曲がりで動く。始点はTAPと同じく触れた瞬間を判定し、中間・終点と一定間隔の判定点では触れているかを判定する。間隔はその位置のBPMで決まり、BPM120未満は16分、240未満は8分、それ以上は4分。中間ノーツから分岐でき、分岐の接続点は親の中間ノーツとして1回だけ判定する |
| BPM変更線 | ノーツが来るタイミング（秒）だけが変わる。ノーツの流れる速さは常に一定（ソフランにはならない） |

総ノーツ数の数え方は譜面エディタ（`SPEC` コマンド）と同じ。譜面の `meta.totalNotes` と一致しない場合は、読み込み時に警告を出す。

### 判定とスコア

スコアは 1ノーツあたり `1,000,000 ÷ 総ノーツ数` を基準に、判定ごとの割合で加算する。全PRECISEで100万点（ALL PRECISE）、全PRECISE+で101万点（理論値）。

| 判定 | 判定幅 | 加算 |
|---|---|---|
| PRECISE+ | ±30ms | 101% |
| PRECISE | ±60ms | 100% |
| APPROX | ±100ms | 50% |
| MISS | ±120ms以内の早押し・遅押し、または見逃し | 0% |

### 難易度

PARALLEL / INTERPLAY / ELUSIVE の3種類。ELUSIVEは一部の楽曲のみ。

## 操作

### 専用コントローラー

| 場所 | 選曲画面での役割 |
|---|---|
| 左斜面（上4・下4レーン） | ソート切り替え ← / →（楽曲確定・設定では戻る） |
| 底面（左5・中央6・右5レーン） | 左 / 決定 / 右 |
| 右斜面（下4・上4レーン） | 難易度 − / +（設定では値の変更） |

通信はシリアル（既定 COM5、115200bps）。パケットはヘッダー `0xAA` ＋ 4バイト（lane 0〜7, 8〜15, 16〜23, 24〜31。各バイトのbit0が一番小さいレーン）。

### キーボード（コントローラー無しでのテスト用）

| キー | プレイ画面 | 選曲画面 |
|---|---|---|
| A / S | lane 0〜3 / 4〜7 | ソート ← / → |
| D / F | lane 8〜11 / 12〜15 | 左 / 決定 |
| J / K | lane 16〜19 / 20〜23 | 決定 / 右 |
| L / ; | lane 24〜27 / 28〜31 | 難易度 − / + |
| F1 | 入力元の切り替え（キーボード / コントローラー / 両方） | − |

選曲画面では ← → Enter Space も使える。

## 譜面

外部のWeb譜面エディタで作成したJSONを使う。

- `meta`：楽曲名・作曲者・難易度・レベル・譜面制作者・音源ファイル名・BPM・オフセットなど
- `notes`：ノーツの配列。位置は `lane`（0〜31）と `width`（レーン数）、時間は `tick`（1小節 = 1920tick、1拍 = 480tick）

## 曲データの置き方

曲データ（譜面・音源・ジャケット）はGoogle Driveで管理していて、**gitには入れない**。Driveから1曲ずつフォルダごと次の場所にコピーする。

```
Assets/StreamingAssets/Songs/<曲フォルダ>/
    譜面JSON（譜面エディタの出力そのまま。難易度ごとに1つ。ファイル名は自由）
    音源ファイル（譜面の meta.audioFileName と同じ名前）
    jacket.png（jacket.jpg でもよい。無ければフォルダ内の最初の画像を使う）
```

- 曲名・作曲者・難易度・レベル・譜面制作者は譜面の `meta` から読むので、曲の情報を書いたファイルは別に作らない
- 難易度は PARALLEL → INTERPLAY → ELUSIVE の順に、低い方から欠けずにそろっている必要がある
- `Songs` に曲が1つも無いときは、選曲画面に仮の曲が表示される（譜面は確認用の `Resources/test_long.json`）
- 読み込めない譜面や足りないファイルがあると、Consoleに警告が出る

## フォルダ構成

```
Assets/
  Scenes/            Opening, MusicSelect, Play, Result
  Scripts/
    Core/            シーン切り替え(SceneLoader)、シーン間のデータ受け渡し(PlaySession)、曲の読み込み(SongLibrary)
    GamePlay/        ノーツ・判定・入力・レーン・リザルト
    MusicSelect/     選曲画面（UIはMusicSelectViewがコードで生成）、楽曲紹介画面
    Opening/         タイトル画面
  StreamingAssets/
    Songs/           曲データ（gitには入れない）
  Resources/         テスト用の譜面JSON
  Prefab/            ノーツ・レーンのプレハブ
```

## 共同開発での注意

- Unityのバージョンを 6000.6.5f1 にそろえる（違うバージョンで開くと大量の差分が出る）
- アセットの移動・名前変更はUnity上で行い、`.meta` ファイルも一緒にコミットする
- シーン（特に Play.unity）は同時に編集しない。作業前に `git pull` する
- コントローラーのポート名など、自分の環境に合わせた値をシーンごとコミットしない
